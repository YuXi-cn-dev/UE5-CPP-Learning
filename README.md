UE5 C++ 学习记录

记录学习 UE5 C++ 的第一个月（聚焦 TArray 与 TMap 容器练习）。

📖 9月学习心得

1. TArray（动态数组）:
 理解：底层是连续内存，随机访问极快。
 常用操作：`Add`、`Emplace`、`Remove` 操作很频繁。
 适用场景：适合需要按顺序遍历和索引访问的场景（如物品栏、队列）。
 踩坑感受：UE 自定义的内存管理，和标准库的 `std::vector` 略有不同，需要适应它的扩容机制。

2. TMap（键值对哈希表）:
  理解：基于哈希表实现，核心优势是 `Find` 和 `Contains` 查找效率极高（平均 O(1)）。
  注意事项：不保证元素顺序，键（Key）必须支持哈希。
  适用场景：需要快速根据 ID 查找数据的场景（如根据角色 ID 查属性、查配置表）。

🚀 阶段总结
一个是顺序存储（TArray），一个是键值映射（TMap）。这个月算是把“存东西”和“找东西”给搞明白了。基础已打牢，接下来尝试将这些数据结构应用到简单的 Gameplay 逻辑中，继续加油！

📖 10月学习心得

3. TSet（集合）
  理解：TSet 是基于哈希表实现的集合，核心特点是元素唯一。它只关心“某个元素在不在”，不关心顺序，也不做键值映射。
  常用操作：添加、包含判断、移除、获取数量是最常用的操作。重复添加同一个元素不会增加数量，这一点和 TArray 区别很大。
  查找效率：包含判断平均是 O(1)，适合高频判断某个东西是否存在；但如果哈希冲突严重，最坏情况会退化。
  注意事项：TSet 不保证遍历顺序，扩容或重新哈希后顺序也可能变化；不能像 TArray 那样按下标索引访问；自定义结构体作为元素时，需要支持相等比较和哈希。
  适用场景：适合去重、已访问标记、标签集合、唯一 ID 集合、技能或状态是否拥有等“存在性判断”场景。
  踩坑感受：刚开始总想用 TSet 当数组遍历，后来发现它更适合“判断有没有”和“顺便去重”，而不是按顺序存数据。

🚀 阶段总结（补充）
9月把“存东西”和“按 key 找东西”搞明白了，10 月又补上了“判断有没有、顺便去重”的 TSet。现在 TArray 管顺序，TMap 管映射，TSet 管唯一性和存在性判断，三者配合起来能覆盖不少基础 Gameplay 数据结构需求。下一步可以尝试做一些简单的UE C++ Gameplay 岗笔试题。
